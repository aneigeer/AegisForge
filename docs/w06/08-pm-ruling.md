## 2. 裁定

**采路径 2。** 具体含义，逐条落地：

1. **W06 阶段定性为已知缺口，不是缺陷自由裁量**：三节在 W06 以 `provided=false` + `reason=NOT_PERSISTED_IN_W06` 如实呈现，且不阻断批准——这是**产品经理批准的阶段性行为**，工程师此前的判断结论（不阻断）**不予追认为越权通过**，其越权点仅在「未上报即自行定档」，已由门禁复核纠正，不另设处分。
2. **不追溯修改 W06 已冻结件**：`docs/w06/05-freeze.md`、`ADR-0005` 的 digest 向量、W06 的 22 条 P0 追溯结论一律保持原状。
3. **把「缺失即阻断」的收紧义务明确转交 W07**：W07 PRD 的 **P0-W07-01** 为唯一承接条，要求三节由服务端事实来源填充、创建时刻快照持久化、并由 `missing_required_fields()` 纳入必需项，缺失时阻止批准。
4. **「批准人可在缺少补偿/验证计划时批准 R2 写操作」登记为显式接受风险 R-1**（见 §5），到期时点为 W07 门禁，不自动续期。
5. 本裁定**不修改** `docs/w06/07-gate-review.md`；门禁结论措辞由架构师据此更新为「放行（附 1 条显式接受风险，到期 W07 门禁）」。

## 3. 为什么不采路径 1（W06 内补 `approvals` 三列 + `ToolDefinition` 三项声明）

| # | 论据 | 说明 |
|---|---|---|
| A1 | **W06 无真实动作可绑定，补列只能填桩值** | 三节的内容本质是「修复方案质量」：补偿动作是什么、成功如何断言——必须绑定**具体动作**才成立。W06 只有测试桩工具且桩工具被明令禁止进入生产注册表（`docs/w06/01-prd.md:81`）。此时补三列，只能填占位/声明性文字，产生「`provided=true` 但内容与真实动作无关」的**假合规**，比如实 `provided=false` 更危险，且直接违反 PRD §4 硬规则②「展示内容与摘要必须同源」。 |
| A2 | **会破坏已冻结的 W06 交付基线** | `docs/w06/05-freeze.md:3` 已声明为冻结证据、任何改动须升 `action_digest_version`；新增列 = 迁移 007 + 回滚脚本 + 重跑四件套复算 + 重做 22 条 P0 追溯，等于把已闭合的 W06 门禁重新打开。 |
| A3 | **会把门禁拖出窗口且收益为零** | W06 门禁窗口已结束（复核完成、向量复算通过）；路径 1 的成本（迁移、重跑审计、再复核）全部花在「一个没有真实动作的周」，而同样的工作量在 W07 是与真实动作一起交付的。 |
| A4 | **路径 2 不是「放过」，而是「定档 + 设截止 + 设门禁」** | 治理要求是「不得以技术实现困难直接放过」。路径 2 给出：显式接受风险清单（R-1）、可机器验证的生效条件（§4）、到期不达成即 W07 门禁不通过。这比「在错误的周里匆忙补一个无内容的字段」更符合 fail closed 的本意。 |
| A5 | **风险敞口经实测为零** | 见 F6：W06 窗口内不存在可执行的写路径，因此「缺补偿/验证计划仍可批准」这一敞口**没有产生任何真实写入**。风险是「规则不严」，不是「已发生损害」——这允许用「设截止期」而非「回滚重做」来处置。 |

## 4. 裁定生效条件（W07 门禁硬条件，可机器验证）

本裁定自签署起生效；**转为闭合**必须同时满足下列 5 条，缺一即视为 W07 门禁不通过，且**不得以「W06 已接受风险」为由续期**：

| # | 生效条件 | 验证方式 |
|---|---|---|
| C1 | `GET /v1/approvals/{approval_id}` 的「风险等级 / 补偿方案 / 验证计划」三节 `provided=true`，且不再出现 `reason=NOT_PERSISTED_IN_W06` | `tests/integration/test_approval_api.py::test_disclosure_three_sections_persisted` |
| C2 | 三节内容来自**服务端事实来源**并持久化（风险 ← `RiskResolver` 解析结果；补偿/验证 ← 工具契约声明），客户端不可提交 | 同 AC-01 + `test_disclosure_snapshot_is_immutable_after_approve`（批准后快照不可改） |
| C3 | 三节纳入 `missing_required_fields()` 必需项；缺失时批准被拒，`details.missing_fields` 明确列出 | `tests/integration/test_approval_service.py::test_approve_blocked_when_disclosure_section_missing` |
| C4 | 存在新迁移（含回滚脚本）把三节落到控制库，且 W06 既有冻结向量**未改变**（`action_digest` 冻结值逐字节不变） | `tests/unit/test_canonical.py::test_frozen_vector_is_byte_exact`、`tests/unit/test_action_digest.py` 全绿 |
| C5 | W07 PRD 的 6 条 P0 全部达成（`docs/w07/01-prd.md` §5 AC-01…AC-15） | W07 门禁复核 |

> 附：若 C1–C4 达成但 W07 其他 P0 未达成，视为「本条已闭合、W07 门禁因其他项不通过」——不得反向把本条重新判为未闭合。

## 5. 显式接受的风险清单

| # | 风险 | 影响 | 为何在 W06 可接受 | 到期 / 关闭条件 | 证据 |
|---|---|---|---|---|---|
| **R-1** | 批准人可在**缺少补偿方案与验证计划**的情况下批准 R2 写操作 | 审批人对「失败后怎么补偿」「成功如何判定」无据可依，批准质量下降 | ① W06 无任何真实写工具（F6/F7），窗口内**实际写入次数为 0**；② 三节如实标注 `provided=false`，未伪装成已提供；③ 敞口被 R-1 自身登记且设有硬到期 | **W07 门禁**：C1–C4 全部达成即关闭；未达成则 W07 门禁不通过 | `apps/api/routes/approvals.py:93-118`、`core/approval/models.py:372-398` |
| **R-2** | 「影响面」中 `reversible` / `affects_other_tasks` 恒为 `null`（同一披露块内的另一处留白） | 审批人无法从接口判断操作是否可逆、是否影响其他任务 | 与 R-1 同源（无数据模型事实来源），且 `missing` 字段已如实返回 `["reversible","affects_other_tasks"]`，未静默隐藏 | **W07 P1-W07-01**（补服务端事实来源）；若不达成，登记至 W08，但必须在 W07 门禁复核中显式列出，不得静默 | `apps/api/routes/approvals.py:88-91` |
| **R-3** | 三节内容**不参与** `action_digest`（W06 冻结的摘要字段集不含三项） | 批准后若有人篡改三节内容，摘要无法检出 | 减轻手段另设：三节在**创建时刻快照并持久化**、批准后不可改（C2）；且三节属「方案说明」而非「操作身份」，操作身份由 `action_digest` 覆盖的参数/目标/环境保证 | W07 设计需明确该口径；若架构师选择纳入摘要，须升 `action_digest_version` 并重算全部冻结向量（不建议） | `docs/w06/05-freeze.md` §D、`docs/w07/01-prd.md` §6-Q2 |

> 三项均为「规则不严 / 展示留白」，**均未造成真实写入或数据损害**。R-1 是本裁定的核心对价，R-2/R-3 为同源衍生，一并登记以免「裁定只关一个口子」形成新的静默缺口。

## 6. 对 W07 的一句话交接

**W07 必须在门禁前把「风险等级 / 补偿方案 / 验证计划」变成由服务端事实填充、创建时刻快照持久化、缺失即阻止批准的必需项（`docs/w07/01-prd.md` P0-W07-01），否则 W07 门禁不通过，且本裁定不接受二次延期。**
